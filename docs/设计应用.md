# 设计应用

本项目展示配套 UI Skill 如何影响一个连续任务。它没有把 50 项技巧全部堆进同一页面，也不代表已有用户实验支持某种效率提升。

| 合集方法 | 页面中的应用 | 检查方式 |
| --- | --- | --- |
| 01 从用户任务确定界面、06 信息层级 | 流水线先给出检查结论与部署入口，再展示阶段、产物和来源 | 检查默认、失败、运行中三种结果；失败时不能继续提交 |
| 07 文字层级、20 字号体系、24 标题与正文行高 | 标题、结果、字段说明使用有限的字号、字重与行高；辅助信息保留可读字号 | 桌面与手机实际截图核对，避免用极小字号削弱信息 |
| 13 操作主次、19 用间距明确归属 | 部署确认按产物、目标环境、说明排列；提交按钮位于核对信息后 | 使用键盘选择环境；提交失败后检查输入仍然保留 |
| 16 按内容确定宽度、17 固定与弹性区域、18 窄屏文字调整 | 桌面分栏、窄屏单列；阶段卡片改为纵向；记录表格局部滚动 | 多个视口检查整页宽度与长名称换行 |
| 29 颜色职责、33 文字对比、34 多种状态线索 | 紫色强调主要操作；状态同时使用文字和图标；正文采用深色 | 不依靠红绿颜色区分结果；对主要文字与背景做颜色计算 |
| 36 视觉高度与层叠、47 空状态、49 重组外观保留语义 | 原生对话框位于顶层，环境选项采用原生单选卡片；区分无记录、筛选无结果、记录缺失 | 用键盘操作单选和对话框；分别清空记录、输入无匹配关键词、访问失效详情 |

## 任务与数据保持一致

- 构建产物使用同一个制品标识，传递到部署确认和结果记录。
- 提交请求失败不创建记录；连续提交只受理一次。
- 请求受理与部署成功分别呈现。已受理的任务还要经过执行阶段。
- 部署失败保留目标环境上次成功版本，重试保留环境与说明。
- 检查通过和有权部署分别判断；前端限制只用于演示，实际鉴权需要服务端。

## 验证范围

自动化检查用于发现状态错误、路由问题和布局溢出；截图检查用于核对可读性与布局。两者均不能替代真实用户的任务测试，也不能据此声明完整无障碍合规。

实际执行结果见 [验收记录](验收记录.md)。
